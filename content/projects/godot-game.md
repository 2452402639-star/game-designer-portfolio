## overview

《爱与刷刷与狗刀特》（AI Brush Rush）是一款融合自动战斗、幸存者式成长与守点塔防的轻量 Roguelite 游戏原型。

这是一次个人游戏开发实践，重点在于通过实际项目理解玩法、系统和完整游戏开发流程。

## core-loop

### 局内循环

1. 进入战斗
2. 自动攻击敌人
3. 击杀获得经验与金币
4. 等级成长与构筑强化
5. 进入更高波次
6. 挑战 Boss

### 局间循环

1. 完成关卡
2. 获得并保留装备
3. 调整携带装备
4. 选择战场
5. 进入下一局

## design-highlights

### 羁绊与吞噬机制

强化不只追求短期数值增长，也希望形成明确的构筑方向与长期目标，让不同选择之间形成组合价值。

吞噬机制用于处理构筑中的冗余资源，减少无效选择和资源堆积。

### 角色专属武器

角色差异不只来自基础属性。专属武器用于强化角色定位，为随机成长提供稳定的成长方向，并作为玩家构筑中的成长锚点。

## iteration

早期的数值调整缺乏明确的体验目标。最初更多依赖直觉修改：

- 伤害
- 血量
- 成长速度
- 倍率

后来发现：

> 数值一直变化，但体验没有形成明确方向。

之后调整思路：先定义玩家体验目标，再从多个维度进行设计：

- 成长节奏
- 构筑方向
- 奖励组合价值
- 金币与装备决策
- 随机性与稳定成长

羁绊机制来源于这一轮迭代。

> 数值本身不是设计目标，数值只是塑造体验的工具。

## role-ai-workflow

### 我主要负责

- 游戏方向与玩法定位
- 核心循环设计
- 系统规则制定
- 角色与构筑方向
- 功能需求拆分
- 体验判断
- 数值调整方向
- 迭代方案
- 内容筛选与最终取舍

### AI 主要辅助

- Godot 代码实现
- 功能原型搭建
- Debug
- 问题定位
- 部分数据分析
- 方案讨论
- 文档整理

> 我提出需求和体验目标 → AI 辅助实现或分析 → 实际游玩 → 判断问题 → 修改设计 → 下一轮实现。

项目主要用于玩法与完整开发流程验证。

部分视觉素材可能使用 AI 辅助或第三方素材完成，主要用于原型展示，不作为个人美术创作成果。正式公开前仍会继续确认素材来源和展示权限。

## project-status

当前版本为 Playable Prototype，仍存在以下不足：

- 内容量不足
- UI 信息层级需要继续调整
- 动画与战斗反馈不足
- 构筑内容不够丰富
- 关卡与敌人差异不足
- 中后期成长体验仍需打磨

## reflection

这个项目最终停留在可运行原型阶段，我没有继续将它扩展成一款完整游戏。

一方面，它最初的目标就是学习并验证从玩法构思到可运行 Build 的完整开发流程；另一方面，当主要系统逐渐跑通后，我也看到了它在内容量、UI、动画表现以及整体完成度上的限制。

相比继续投入大量时间补齐内容，我更希望把这次项目中积累的方法带到之后的新项目中。

对我来说，《爱与刷刷与狗刀特》最重要的成果并不是完成了多少功能，而是第一次比较完整地经历了：

> 想法 → 实现 → 实际游玩 → 发现问题 → 修改设计 → 再验证

这个循环。

它也让我更加明确：

> 游戏设计不能只停留在文档里的合理。真正运行起来之后，很多原本看似正确的设计问题才会暴露出来。

这也是我之后希望继续通过个人项目保持的学习方式。
